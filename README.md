Описание структуры проекта MyRestAPI (АРМ «Страхование населения»):

Проект поделён на три слоя:

1. Common — «словарь и правила»
Здесь описано, что вообще есть в системе: клиент, договор, менеджер, страхуемый объект, вид страхования, филиал. Каждый класс сам проверяет свои данные (паспорт, телефон, email, суммы, даты) и не даёт создать «кривую» запись. Тут же лежат интерфейсы, то есть список того, что должна уметь база данных (найти клиента, сохранить договор и т. д.), но не как.

2. Drivers — «как именно хранить»
Реальная работа с базой:

SQLite: один файл, ничего устанавливать не надо, удобно для разработки и показа на защите.
MariaDB: настоящий сервер для боевой работы, где сидит много менеджеров сразу.

Обе реализации выполняют один и тот же интерфейс, поэтому они взаимозаменяемы. Каждая таблица вынесена в свой файл, чтобы не получилась одна огромная «каша» на тысячи строк.

3. API — «приёмная»
Принимает запросы по HTTP, разбирает JSON, обращается к базе только через интерфейс и возвращает ответ. Если данные неверные, отдаёт ошибку 400. Про устройство базы она ничего не знает.

Главная идея: API не привязан к конкретной базе. Чтобы переключиться с SQLite на MariaDB, достаточно поменять одну строчку в Program.cs. Плюс так легче тестировать: можно подсунуть фейковую базу.
